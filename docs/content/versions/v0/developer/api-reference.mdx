The web application serves both an interactive API reference and a machine-readable OpenAPI document.

| URL                         | Content                              |
| --------------------------- | ------------------------------------ |
| `/api/docs`                 | Interactive API reference            |
| `/api/docs/openapi.json/v0` | Machine-readable v0 OpenAPI document |

The OpenAPI document describes the client-credentials scheme used by protected `/api/v0/**` endpoints. The built-in `cli`
client is a [system-managed service principal](./oauth-clients). Request a local access token from `/oauth2/token`, then
authorize requests with the returned bearer token.

```bash
curl -u "${SPRING_SECURITY_OAUTH2_AUTHORIZATIONSERVER_CLIENT_CLI_REGISTRATION_CLIENTID}:${SPRING_SECURITY_OAUTH2_AUTHORIZATIONSERVER_CLIENT_CLI_REGISTRATION_CLIENTSECRET}" \
  -d grant_type=client_credentials \
  -d scope=taskmigo.api \
  http://localhost:8080/oauth2/token
```

## v0 package boundaries

API v0 separates feature code from shared HTTP infrastructure:

```text
io.taskmigo.web.api.v0
├── feature
│   └── <feature>
└── infrastructure
    ├── response
    └── security
```

Put controllers and feature-specific exception translation under `feature.<feature>`, for example
`feature.resource`. Put reusable v0 transport concerns under `infrastructure`. Feature packages may depend on infrastructure;
infrastructure must not depend on a concrete feature package.

The shared response classes are under `io.taskmigo.web.api.v0.infrastructure.response`.

## v0 response envelope

Every `/api/v0/**` controller must return `ApiResponse` through `ApiResponseFactory`. Do not build the envelope manually in a
controller. The factory keeps status codes, messages, execution metadata, errors, and pagination consistent across features.

`ApiResponse` has the form `ApiResponse<Data, Meta>`. `Data` is the endpoint payload. `Meta` is part of the endpoint contract
and determines whether the generated OpenAPI response contains pagination.

### Choose the meta type per endpoint

Use `ApiResponse.BasicMeta` when the endpoint returns the complete data set or pagination is not applicable. In this case,
`meta.pagination` is absent from both the serialized response and the generated OpenAPI schema.

Use `ApiResponse.OffsetMeta` when the endpoint implements page/offset pagination. The endpoint must pass an
`ApiResponse.OffsetPagination` value to the matching `ApiResponseFactory.ok(...)` overload. OpenAPI then exposes only the
offset pagination shape.

Use `ApiResponse.CursorMeta` when the endpoint implements cursor pagination. The endpoint must pass an
`ApiResponse.CursorPagination` value to the matching `ApiResponseFactory.ok(...)` overload. OpenAPI then exposes only the
cursor pagination shape.

The controller method signature is the source of truth for OpenAPI. Never declare a general pagination type for an endpoint.
An endpoint must expose exactly the pagination strategy it implements.

### Common usage

For an endpoint without pagination, declare a return type such as
`ResponseEntity<ApiResponse<Set<String>, ApiResponse.BasicMeta>>` and call
`responses.ok(data, messageCode, messageText)`.

For offset pagination, declare a return type such as
`ResponseEntity<ApiResponse<List<ItemDto>, ApiResponse.OffsetMeta>>`, build an `ApiResponse.OffsetPagination` from the service
result, and call `responses.ok(data, pagination, messageCode, messageText)`.

For cursor pagination, declare a return type such as
`ResponseEntity<ApiResponse<List<EventDto>, ApiResponse.CursorMeta>>`, build an `ApiResponse.CursorPagination` from the service
result, and call `responses.ok(data, pagination, messageCode, messageText)`.

Use `responses.created(...)` for successful creation endpoints and `responses.ok(...)` for successful operations that do not
create a resource. These non-list mutation responses use `BasicMeta` because pagination is not applicable.

Feature-specific exception handlers should translate domain exceptions into the shared v0 envelope through
`ApiResponseFactory.failure(...)`. Common validation, malformed-request, fallback, and security errors are already handled by
the shared v0 infrastructure.

## OpenAPI rules

When adding or changing a `/api/v0/**` endpoint:

1. Declare `ApiResponse<Data, ApiResponse.BasicMeta>`, `ApiResponse<Data, ApiResponse.OffsetMeta>`, or
   `ApiResponse<Data, ApiResponse.CursorMeta>` explicitly in the controller return type.
2. Use the matching `ApiResponseFactory` overload.
3. Use `BasicMeta` when the endpoint returns the complete data set. Do not return `pagination: null`.
4. Never use `oneOf` to advertise multiple pagination strategies for one endpoint.
5. Verify `/api/docs/openapi.json/v0` and ensure the operation shows exactly the pagination contract implemented by that API.

`ApiV0ResponseContractTest` enforces that every v0 controller returns the standard envelope. OpenAPI integration coverage must
also be updated when introducing a new pagination shape or changing how an endpoint is documented.
